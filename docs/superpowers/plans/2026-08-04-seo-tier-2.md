# SEO Tier 2 — Real Routes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert six client-state screens into eight real, statically-prerendered routes, replacing the product modal with product pages — taking the site from 1 indexable URL to 8 and fixing per-page analytics as a side effect.

**Architecture:** The app chrome moves into the root layout as a client `AppShell` wrapping `{children}`. Each route's page renders its own `ScreenShell`, which is the `.screen-scroll` container — so a route change remounts a fresh scroll container at `scrollTop: 0`, exactly the mechanism the iOS Safari fix depends on. `lib/store.tsx` is reduced to overlay state only.

**Tech Stack:** Next.js 15.5.22 App Router · React 18 · TypeScript · Tailwind · Framer Motion · anime.js

**Design doc:** `docs/superpowers/specs/2026-08-04-seo-tier-2-real-routes-design.md`

---

## ⚠️ Read before touching anything

**The scroll model is the highest-risk thing in this repo.** `HANDOFF.md` documents it as the fix for iOS Safari ignoring `scrollTo`/`scrollTop`/`scrollIntoView` after a client-side view swap. Three invariants:

1. `body { height: 100%; overflow: hidden }` — the document never scrolls.
2. Each screen root is a `.screen-scroll` container (`height:100%; overflow-y:auto`).
3. Navigating **unmounts** the old container and mounts a brand-new one.

`ScreenShell` must stay **inside each page**, never hoisted into the layout. If it moves to the layout it persists across routes, stops remounting, and the iOS bug returns — silently, because it only manifests on real iOS hardware.

Task 1 adds a mechanical assertion for invariant 1. Invariants 2 and 3 are structural: keep `ScreenShell` in pages.

**Also banned:** `layoutId` on any element inside a subtree an `AnimatePresence` removes. That produced a wedged, undismissable sheet earlier today (see the Gotchas section of `HANDOFF.md`). Route transitions add more places to trip on it.

**Files:** Create `lib/routes.ts`, `app/{bars,nutrition,ordering,wholesale,about}/page.tsx`; modify `app/page.tsx`, `lib/store.tsx`, `components/{Header,StickyNav,MobileMenu,AppShell}.tsx`; delete `components/App.tsx`

- [ ] **Step 1: Create `lib/routes.ts`**

```ts
import type { ProductId } from "./content";

/**
 * Single source of truth for paths. The nav, the sitemap and per-page metadata
 * all read from here, so a route cannot exist in one and be missing from
 * another — which is exactly how a page ends up unlinked and unindexed.
 */
export const ROUTES = {
  home: "/",
  bars: "/bars",
  nutrition: "/nutrition",
  ordering: "/ordering",
  wholesale: "/wholesale",
  about: "/about",
} as const;

export type RouteKey = keyof typeof ROUTES;

/** URLs stay English even when the UI is Arabic — slugs are not localized. */
export const PRODUCT_SLUGS: Record<ProductId, string> = {
  cookie: "oat-cookie-bar",
  protein: "oat-protein-bar",
};

export const productPath = (id: ProductId) => `${ROUTES.bars}/${PRODUCT_SLUGS[id]}`;

/** Reverse lookup for the [slug] route. */
export const productIdFromSlug = (slug: string): ProductId | null => {
  const hit = (Object.keys(PRODUCT_SLUGS) as ProductId[]).find(
    (id) => PRODUCT_SLUGS[id] === slug,
  );
  return hit ?? null;
};

/** Former hash views, for redirecting links shared before Tier 2. */
export const LEGACY_HASH_ROUTES: Record<string, string> = {
  bars: ROUTES.bars,
  nutrition: ROUTES.nutrition,
  ordering: ROUTES.ordering,
  wholesale: ROUTES.wholesale,
  about: ROUTES.about,
};
```

- [ ] **Step 2: Create `app/bars/[slug]/page.tsx`**

```tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { CONTENT } from "@/lib/content";
import { PRODUCT_SLUGS, productIdFromSlug } from "@/lib/routes";
import ProductScreen from "@/components/screens/ProductScreen";

export function generateStaticParams() {
  return Object.values(PRODUCT_SLUGS).map((slug) => ({ slug }));
}

export const dynamicParams = false;

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>;
}): Promise<Metadata> {
  const { slug } = await params;
  const id = productIdFromSlug(slug);
  if (!id) return {};
  const p = CONTENT.en.products[id];
  return {
    title: `${p.name} | Candy Couture`,
    description: `${p.description} ${p.pricePerBar} per bar, ${p.pricePerBox} per pack of 10. Handmade in Bahrain.`,
    alternates: { canonical: `/bars/${slug}` },
  };
}

export default async function ProductPage({
  params,
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const id = productIdFromSlug(slug);
  if (!id) notFound();
  return <ProductScreen productId={id} />;
}
```

> `params` is a Promise in Next 15 — this is one of the App Router's breaking changes from 14. Awaiting it is required, not optional.

`ProductScreen` takes `productId` and reads the localized product itself via `useContent()`, so the page stays language-agnostic.
