# SEO Tier 1 — Crawlability, Structured Data & Asset Weight

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the site crawlable and machine-readable — `robots.txt`, `sitemap.xml`, canonical URL, schema.org structured data — and strip ~750 KB of needless image weight, so Google can discover and index the homepage at all.

**Architecture:** Everything here is additive and server-rendered. Next 15's `app/robots.ts` and `app/sitemap.ts` file conventions generate the two text routes at build time. Structured data is built from the existing `lib/content.ts` source of truth by a new `lib/seo.ts` and emitted from the root layout (a server component), so it lands in the initial HTML. No routing, no client components, no changes to the app-shell scroll model.

**Tech Stack:** Next.js 15.5.22 App Router · TypeScript · `sharp` (already present via the Next 15 override) for image resizing · a dependency-free Node assertion script for verification.

---

## Scope

This plan is **Tier 1 only**. Tiers 2 and 3 from `HANDOFF.md` are separate subsystems and get their own plans:

- **Tier 2** (real routes + per-product pages) — a routing refactor that conflicts with the app-shell scroll model and needs its own design work.
- **Tier 3** (`/ar` routes + hreflang) — depends on Tier 2 landing first.

**Set expectations honestly before starting:** Tier 1 will *not* fix the "227 characters of indexable text" problem. After this plan the site will still have exactly **one** indexable URL. What changes is that Google can now *find* and *understand* that URL — today it has indexed **zero** pages. Going 0 → 1 indexed with rich product data is the prerequisite for everything else, not the finish line.

**Why `lib/seo.ts` rather than extending `lib/content.ts`:** `content.ts` is the *bilingual display* bundle — its `pricePerBar` values are localized strings (`"1.5 BD"` / `"1.5 د.ب"`). schema.org needs a bare number plus an ISO 4217 currency code. Parsing numbers back out of localized strings would be fragile, so the numeric facts live in one non-localized place, and names/descriptions are still read from `CONTENT.en`.

```js
#!/usr/bin/env node
// Dependency-free SEO assertions against a running build.
//   npm run build && npm run start -- -p 3200
//   npm run seo:check                     # defaults to http://localhost:3200
//   npm run seo:check -- https://www.candycouture.co
//
// Exits non-zero if any assertion fails, so it can gate a deploy.

const BASE = (process.argv[2] || process.env.SEO_BASE || "http://localhost:3200").replace(/\/$/, "");
const CANON = "https://www.candycouture.co";

let passed = 0;
const failures = [];

function check(name, ok, detail = "") {
  const suffix = detail ? ` — ${detail}` : "";
  if (ok) {
    passed++;
    console.log(`  ✓ ${name}`);
  } else {
    failures.push(name + suffix);
    console.log(`  ✗ ${name}${suffix}`);
  }
}

const get = (path) => fetch(BASE + path, { cache: "no-store" });

async function main() {
  console.log(`SEO check against ${BASE}\n`);

  // ── robots.txt ──────────────────────────────────────────────
  const robots = await get("/robots.txt");
  check("robots.txt returns 200", robots.status === 200, `got ${robots.status}`);
  const robotsBody = robots.status === 200 ? await robots.text() : "";
  check("robots.txt allows crawling", /user-?agent:\s*\*/i.test(robotsBody) && /allow:\s*\//i.test(robotsBody));
  check("robots.txt points at the sitemap", robotsBody.includes(`${CANON}/sitemap.xml`));

  // ── sitemap.xml ─────────────────────────────────────────────
  const sitemap = await get("/sitemap.xml");
  check("sitemap.xml returns 200", sitemap.status === 200, `got ${sitemap.status}`);
  const sitemapBody = sitemap.status === 200 ? await sitemap.text() : "";
  check("sitemap.xml is a urlset", sitemapBody.includes("<urlset"));
  check("sitemap.xml lists the canonical homepage",
    sitemapBody.includes(`<loc>${CANON}/</loc>`) || sitemapBody.includes(`<loc>${CANON}</loc>`));

  // ── homepage head ───────────────────────────────────────────
  const home = await get("/");
  check("homepage returns 200", home.status === 200, `got ${home.status}`);
  const html = home.status === 200 ? await home.text() : "";
  check("canonical points at the www host",
    html.includes(`rel="canonical" href="${CANON}/"`) || html.includes(`rel="canonical" href="${CANON}"`));
  check("og:url present", /property="og:url"/.test(html));

  // ── structured data ─────────────────────────────────────────
  const ld = html.match(/<script type="application\/ld\+json"[^>]*>([\s\S]*?)<\/script>/);
  check("JSON-LD block present", !!ld);
  if (ld) {
    let graph = null;
    try {
      const parsed = JSON.parse(ld[1]);
      graph = parsed["@graph"] || [parsed];
    } catch {
      /* graph stays null */
    }
    check("JSON-LD parses as valid JSON", !!graph);
    if (graph) {
      const types = graph.map((n) => n["@type"]);
      check("JSON-LD includes an Organization", types.includes("Organization"));
      const products = graph.filter((n) => n["@type"] === "Product");
      check("JSON-LD includes both products", products.length === 2, `found ${products.length}`);
      check("every product carries a BHD offer",
        products.length > 0 && products.every(
          (p) => p.offers && p.offers.priceCurrency === "BHD" && Number(p.offers.price) > 0));
    }
  }

  // ── regression guard: never lose Search Console ─────────────
  const gsc = await get("/google84764bf90bc17c8e.html");
  check("Search Console verification file still served", gsc.status === 200, `got ${gsc.status}`);

  // ── asset weight budgets ────────────────────────────────────
  const budgets = [
    ["/icon.png", 20],
    ["/images/icons/wholegrain-oats-v3.png", 20],
    ["/images/icons/dark-chocolate-chunks-v3.png", 20],
    ["/images/icons/smart-snacking-v3.png", 20],
  ];
  for (const [path, maxKB] of budgets) {
    const res = await get(path);
    if (res.status !== 200) {
      check(`${path} under ${maxKB}KB`, false, `got ${res.status}`);
      continue;
    }
    const kb = Math.round((await res.arrayBuffer()).byteLength / 1024);
    check(`${path} under ${maxKB}KB`, kb <= maxKB, `${kb}KB`);
  }

  console.log(`\n${passed} passed, ${failures.length} failed`);
  if (failures.length) process.exit(1);
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});
```

```ts
import { CONTACT, CONTENT, type ProductId } from "./content";

/**
 * Canonical origin. MUST stay in sync with `metadataBase` in app/layout.tsx.
 * The apex (candycouture.co) 301s here, so this is the only host that should
 * ever appear in a sitemap, canonical tag or structured-data URL.
 */
export const SITE_URL = "https://www.candycouture.co";

/**
 * Per-bar price in BHD, for structured data only.
 *
 * content.ts holds *localized display copy* ("1.5 BD" / "1.5 د.ب"), but
 * schema.org needs a bare number plus an ISO 4217 currency code. Parsing the
 * number back out of a localized string would break the moment the Arabic
 * formatting changes, so the numerics live here instead. Names and
 * descriptions are still read from content.ts — this is not a second source
 * of truth for anything that already exists there.
 */
export const PRICE_PER_BAR_BHD: Record<ProductId, number> = {
  cookie: 1.5,
  protein: 1.8,
};

/**
 * Minimum order in bars, mirroring `moq` in content.ts (a display string,
 * "10 pieces"). Emitted as `eligibleQuantity` so the advertised per-bar price
 * is not read as "you can buy exactly one for 1.50 BD" — you cannot; one pack
 * of 10 is the smallest purchase.
 */
export const MIN_ORDER_BARS = 10;

/**
 * The schema.org graph emitted into the document head.
 *
 * Deliberately `Organization`, not `LocalBusiness`. LocalBusiness rich results
 * expect a real postal address, geo coordinates and opening hours; there is no
 * public storefront address to publish, and inventing one would be worse than
 * omitting the type. If a real address exists later, upgrade `@type` to
 * `FoodEstablishment` and add `address`, `geo` and `openingHoursSpecification`.
 *
 * English only: structured data describes the entity, not the page language,
 * and the Arabic bundle carries identical facts.
 */
export function buildJsonLd() {
  const c = CONTENT.en;

  const organization = {
    "@type": "Organization",
    "@id": `${SITE_URL}/#organization`,
    name: c.brand.name,
    url: SITE_URL,
    logo: `${SITE_URL}/images/candy-couture-logo.png`,
    image: `${SITE_URL}/opengraph-image.png`,
    description: c.hero.subtext,
    email: CONTACT.email,
    areaServed: { "@type": "Country", name: "Bahrain" },
    sameAs: [CONTACT.instagramUrl],
    contactPoint: {
      "@type": "ContactPoint",
      contactType: "sales",
      telephone: CONTACT.whatsapp.replace(/\s/g, ""),
      areaServed: "BH",
      availableLanguage: ["en", "ar"],
    },
  };

  const products = (Object.keys(PRICE_PER_BAR_BHD) as ProductId[]).map((id) => {
    const p = c.products[id];
    return {
      "@type": "Product",
      "@id": `${SITE_URL}/#product-${id}`,
      name: p.name,
      description: p.description,
      image: `${SITE_URL}${p.image}`,
      brand: { "@type": "Brand", name: c.brand.name },
      offers: {
        "@type": "Offer",
        price: PRICE_PER_BAR_BHD[id].toFixed(2),
        priceCurrency: "BHD",
        availability: "https://schema.org/InStock",
        url: SITE_URL,
        seller: { "@id": `${SITE_URL}/#organization` },
        eligibleQuantity: {
          "@type": "QuantitativeValue",
          minValue: MIN_ORDER_BARS,
          unitText: "bars",
        },
      },
    };
  });

  return { "@context": "https://schema.org", "@graph": [organization, ...products] };
}
```

```tsx
import { buildJsonLd } from "@/lib/seo";

/**
 * Emits the schema.org graph as JSON-LD.
 *
 * A server component on purpose: this has to be in the initial HTML, unlike
 * the rest of the site's content, which is client-rendered behind view state
 * and therefore invisible to crawlers. Until Tier 2 lands, this block is the
 * only machine-readable description of the products that exists.
 *
 * `<` is escaped because a literal "</script>" anywhere in the content would
 * otherwise close this tag early.
 */
export default function JsonLd() {
  const json = JSON.stringify(buildJsonLd()).replace(/</g, "\\u003c");
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: json }}
    />
  );
}
```

## Task 6: Cut image weight

The favicon is a **298 KB, 1276×1277 PNG** that every visitor downloads to draw a 32px tab icon. The three hero benefit icons total **~480 KB** and are loaded as CSS masks via `MaskIcon`, so they bypass `next/image` entirely and ship at full size — to be displayed at 48px.

**Correction to the original audit:** it recommended converting the mask icons to SVG. That would need the artwork re-authored or vector-traced, which is design work, not a code change. Downscaling to 144×144 (3× the 48px display size) captures nearly the same saving with zero design risk, because `MaskIcon` renders them as flat single-colour silhouettes where source resolution above 3× is invisible.

- [ ] **Step 3: Write the resize script**

Create `scripts/optimize-assets.mjs`:

```js
#!/usr/bin/env node
// One-shot image downsizing. Re-runnable, but only needs running when the
// source artwork changes.
//
//   npm run assets:optimize
//
// icon.png is overwritten in place because Next content-hashes the favicon URL
// (/icon.png?<hash>), so caches bust automatically. The mask icons are served
// straight from public/ with a stable URL, so they get a -v3 suffix instead —
// the same cache-busting convention the repo already uses for -v2.

import sharp from "sharp";
import { readFile, writeFile } from "node:fs/promises";

const JOBS = [
  { from: "app/icon.png", to: "app/icon.png", size: 96 },
  {
    from: "public/images/icons/wholegrain-oats-v2.png",
    to: "public/images/icons/wholegrain-oats-v3.png",
    size: 144,
  },
  {
    from: "public/images/icons/dark-chocolate-chunks-v2.png",
    to: "public/images/icons/dark-chocolate-chunks-v3.png",
    size: 144,
  },
  {
    from: "public/images/icons/smart-snacking-v2.png",
    to: "public/images/icons/smart-snacking-v3.png",
    size: 144,
  },
];

for (const job of JOBS) {
  const before = (await readFile(job.from)).byteLength;
  const out = await sharp(job.from)
    .resize(job.size, job.size, {
      fit: "contain",
      background: { r: 0, g: 0, b: 0, alpha: 0 },
    })
    .png({ compressionLevel: 9 })
    .toBuffer();
  await writeFile(job.to, out);
  const kb = (n) => Math.round(n / 1024);
  console.log(`${job.from} -> ${job.to}   ${kb(before)}KB -> ${kb(out.byteLength)}KB`);
}
```

Add the npm script in `package.json`:

```json
    "seo:check": "node scripts/seo-check.mjs",
    "assets:optimize": "node scripts/optimize-assets.mjs"
```

- [ ] **Step 2: Add a property that actually covers `www`**

The current property reports on the apex only, which is why it shows one URL and classifies it "Page with redirect."

**Preferred — a Domain property.** In Search Console, *Add property* → *Domain* → `candycouture.co`. This covers apex, `www`, `http` and `https` in one property and survives any future host change. It verifies by DNS TXT record, which you add in GoDaddy alongside the existing DNS entries.

**Fallback if DNS is awkward — a URL-prefix property** for `https://www.candycouture.co`. The existing `google84764bf90bc17c8e.html` file is already served on that host, so it verifies immediately with no DNS change.

Keep the old apex property. It is harmless and confirms the redirect is being followed.

In the new property: *Sitemaps* → enter `sitemap.xml` → Submit.

Expected: status *Success*, 1 discovered URL. If it reports *Couldn't fetch*, re-check `npm run seo:check -- https://www.candycouture.co` — the sitemap is almost certainly 404ing on the host the property covers.

- [ ] **Step 4: Request indexing for the homepage**

*URL Inspection* → `https://www.candycouture.co/` → *Request indexing*.

This is the single action most likely to move "Indexed: 0" off zero, because it bypasses the discovery problem entirely rather than waiting for a recrawl.
